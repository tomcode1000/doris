What went wrong, and the fixes (all in `trap/door.py`, tested in `tests/test_trap_door.py`):

1. `sprite-env` hangs when called from a service (waits on stdin) -> the door talks
   to `/.sprite/api.sock` directly with stdin closed.
2. When the caller hung up mid-reply, the door crashed before rewinding -> rewind
   now runs in `finally`.
3. Fly's restore call sometimes stalls -> a `DIRTY` marker (not in the clean
   checkpoint, so only a real rewind removes it) makes the trap refuse all work
   until it is clean, and a watchdog keeps retrying. Observed recovery: about 30
   minutes after a stall; never reused dirty.
4. Back-to-back links found the trap still rewinding -> doris-home now waits for
   `/health` to report clean before sending the next link.

Fly refuses Custom API connectors that target the Sprites API itself
(`blocked: base URL targets the Sprites API itself`), which is why the trap
rewinds itself rather than being rewound by doris-home.
