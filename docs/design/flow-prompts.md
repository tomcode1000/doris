# Flow prompts for the Doris website

Rule: Flow gets facts and page contents only. It makes every design decision.
Consistency: page 1 first; pages 2-5 attach the chosen page 1 image.
Settings: Nano Banana 2.1, 16:9, 2 outputs. No upscaling.

## Shared opening (start of every prompt)

Design an institutional website for "Doris". Every visual decision is yours; I give only facts and contents. Reject templates, SaaS patterns and AI slop: original, flawless. One widescreen 16:9 desktop page, full length, no browser or device frame. Real, legible, correctly spelled English; invent no numbers, people, organisations, logos or claims.

FACTS: Doris is a fictional 81-year-old run by an AI agent (Fly.io Hacksgiving 2026). Families forward scam emails to ask-doris@agentmail.to; she says if it is a scam, then writes back to the scammer from doris.pemberton@agentmail.to, slow and chatty, giving nothing real. Scam links open in a separate computer wiped after every visit; she records what the page wanted and reports phishing sites. Never sends money, never mentions the family, never threatens. Public diary and tamper-evident log. Readers: adult children of older parents; hackathon judges.

## 1. Landing

CONTENTS: name and one-line promise; what she does; both addresses; how it works (3-4 steps); numbers: 1 case, 1 letter, 7 links examined, 0 sites reported; latest diary entry quoting: "Dear Barrister James, well that's a surprise, I didn't know I had a relative with that sort of money. Reg would've said it's too good to be true, but Reg always was a worrier. Which relative was it, dear?"; what she never does; navigation: Diary, Case files, How it works, Evidence.

## Pages 2-5 opening (after the shared opening)

Attached is the landing page you designed for this site. Design the next page of the same website with the same design system, so the whole site is consistent.

## 2. Diary

CONTENTS: Doris's public record, newest first. Entry types: case opened; letter Doris wrote (signed "Love, Doris x"); scammer reply (untrusted, links shown unclickable like hxxps://example[.]test); link examined (what the page asked for, or that it fled to the real site); site reported; fake login that came back. Each entry has a time and case number (CASE 0001). Filter by entry type. Shows the log chain is intact.

## 3. Case file

CONTENTS: one case: CASE 0001, advance-fee scam, opened 27 Nov 2026, status active, sender withheld; the back-and-forth letters (the real Doris letter above); evidence: pages examined and what they asked for, report status; the case's log entries with short hashes.

## 4. How it works

CONTENTS: one scam's journey from forward to report; where keys live (a vault outside both computers, never inside them); why the link-opening computer is wiped after every visit; what Doris will never do, each rule shown with the automated test that enforces it.

## 5. Evidence

CONTENTS: measured results: scams engaged 29 of 29; genuine emails engaged 0 of 19; hidden instructions to the AI judged safe 0 of 4; median decision 2.6 seconds; link-opening computer refused by all 4 services (403); 164 automated tests. A plain note that the evaluation set is small and synthetic. Links to the code and run records.
